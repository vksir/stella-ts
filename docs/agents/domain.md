# 领域文档

工程 skill 探索代码库时应如何消费本仓库的领域文档。

## 探索前先读

- 仓库根 `GLOSSARY.md`
- `docs/adr/`：阅读与你将要改动的区域相关的 ADR

若文件不存在，**静默继续**：不要提示缺失，也不要预先建议创建。`/domain-modeling` skill（经 `/grill-with-docs` 等到达）会在术语或决策真正敲定时惰性创建它们。

## 文件结构（单上下文）

    /
    ├── GLOSSARY.md
    ├── docs/adr/
    │   ├── 0001-….md
    │   └── …
    └── （源码）

## 使用词汇表的语言

输出中出现领域概念（议题标题、重构提案、假设、测试名）时，使用 `GLOSSARY.md` 定义的术语，不要漂移到词汇表明确标注 _Avoid_ 的同义词。

需要的概念还不在词汇表里时，这是个信号：要么你在发明项目不用的语言（请重新考虑），要么存在真实缺口（记下来交给 `/domain-modeling`）。

## 标记 ADR 冲突

输出与现有 ADR 矛盾时，显式指出而不是悄悄覆盖：

> _与 ADR-0007（…）矛盾，但值得重开，因为……_
