# 用登录密钥取代「本机即可信」

> **Status: 已采纳**。取代 [ADR-0001](0001-pi-durable-sse-vite-stack.md) 中
> 「单用户本机部署下接受此风险」这一前提。

Stella 能读写文件、执行命令，而服务端原先监听全部网卡且没有任何身份校验：
同一 Wi-Fi 或公网上的任何人都能打开页面、让 Agent 在自己机器上执行命令。
本 ADR 把「谁能用」从隐含假设变成一道显式的门：**只有持有登录密钥的人能使用**。

## Decision

- **一把锁，没有用户系统**。全进程只有一枚登录密钥（`STELLA_TOKEN`），由部署者保管；
  没有账户、角色、权限，也没有多令牌（每个设备一份）。
- **密钥只在服务端**。浏览器提交密钥换取一枚 HMAC 签名的**票据**（`v1.<签发时间>.<签名>`），
  之后所有请求带 `Authorization: Bearer <票据>`。票据无状态，服务端不存会话表。
- **30 天固定过期，不滑动续期**。过期即重新输入；续期逻辑省掉，行为可预期。
- **退出仅清本浏览器**。服务端没有撤销表，无法单独吊销某一台设备；
  要让所有浏览器重新登录，就轮换登录密钥并重启进程。这是「无状态 + Bearer」的必付账，
  写在 README 里，而不是悄悄不写。
- **首次部署自动生成**。没有 `STELLA_TOKEN` 时生成一枚并追加进已存在的 `.env`；
  找不到可写的 `.env` 就报错并提示 `npm run token:gen`。faux 模式与测试不启用登录。
- **SSE 改 `fetch` 读流**。`EventSource` 无法自定义请求头（规范限制），所以实时通道改为
  `fetch` 读流并手写帧解析（`web/src/sse.ts`）；凭据只走请求头，URL 里不出现任何凭据。
- **默认绑定回环地址**。`STELLA_HOST` 缺省 `127.0.0.1`，对外必须显式设置。
  这是与登录密钥独立的第二道兜底：忘了配密钥时，外面连端口都连不上。
- **不做 CSRF 防护，也不校验 Origin/Host**。Bearer 不会被浏览器自动附带，
  CSRF 与 DNS rebinding 都拿不到凭据；TLS 由反向代理终止。

## Considered Options

- **Cookie（HttpOnly + SameSite）**：更安全（XSS 偷不到凭据）、SSE 无需改动。被否——
  用户明确选择 Bearer；且 Cookie 方案需要 CSRF 配套（SameSite + Origin 校验），
  而本项目不打算做 Origin 校验。
- **本地存登录密钥本体**：少一层签名逻辑。被否——密钥会躺在 `localStorage` 等 XSS 来拿，
  过期时间也只能由客户端自觉；签发票据让轮换天然生效。
- **多条具名令牌 / 撤销表**：可按设备吊销。被否——与「无用户系统、无状态」冲突，
  且对单人自托管场景收益很低。
- **SSE 走 `?token=`**：把长期凭据写进访问日志、浏览器历史与 Referer。被否——最终选 fetch 流，
  零新增依赖，且与上游 `pi-ai` 的流式实现一致。
- **滑动续期（30 天不用才失效）**：体验更好。被否——用户选择固定 30 天。

## Consequences

- 前端没有任何路由库，登录页是 `App` 顶部的一个状态分支（`checking` / `gated` / `ready`），
  不是一条路由；401 中途失效会退回门禁，但**不销毁前端 store**，未发送的草稿还在。
- `EventSource` 被移除，`web/src/store/app-store.ts` 的实时通道改为 fetch 读流；
  断线重连、静默守护（20s/60s）、`?from=` 续订语义保持不变，由 `web/src/sse.ts` 的帧解析承担。
- 票据 30 天固定过期意味着：一台不再使用的设备，其票据在到期前仍然有效。
- 登录失败按来源地址限速（60 秒内 5 次），失败日志只记来源与次数，不记用户输入。
- 测试与 faux 体验免登录（服务端只在显式配置了 `STELLA_TOKEN` 时才启用），
  因此现有 16 个服务端测试无需改动鉴权装配。
